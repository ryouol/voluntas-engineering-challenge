I built a Rust collector for all live regular Kalshi markets, using Voluntas's supplied SBE template. The submission focuses on the core challenge: market discovery, ordered book updates, minute snapshots, and a clean shutdown.

The approach

I started from the official template and kept its schemas and reader. I adapted its writer to accept stdout or a file while preserving the existing chunk format. The collector is split around ownership: one task owns each connection and its books; one writer owns the output stream.

1. Discover membership safely

REST discovery follows every page with mve_filter=exclude. A full scan runs on a 60-second schedule, alongside lifecycle notifications. A failed scan retains the previous membership set. New lifecycle observations override stale scan results, so a slow scan cannot undo a more recent activation or closure.

2. Balance markets and preserve ownership

New markets go to the socket with the fewest assigned markets; existing assignments stay stable. The configurable target starts at 100 markets per socket and grows to fit the configured connection budget. At least two data sockets are used when multiple markets exist. These are application defaults, not claims about an exchange limit.

If a market changes owners, the coordinator waits until its old owner has finished queuing records before allowing the new owner to start. This prevents old updates from arriving after a new snapshot in the output.

3. Apply exact, ordered book changes

Prices and quantities are integers in millionths. A NO bid becomes a YES ask at 1 − price. Signed exchange changes update the local book; emitted quantities are absolute. Zero deletes the price level.

NO bid:     price 0.37, quantity 12.50
YES ask:    price 0.63, quantity 12.50
Delta:                 quantity −2.50
SBE update: price 630000, quantity 10000000

A snapshot must arrive before deltas can be applied. Sequence numbers are checked per subscription, including when several markets share one sequence. A gap or disconnect discards that socket's books and rebuilds them from fresh snapshots.

4. Produce output that can be checked

The collector emits initial snapshots, recovery snapshots, updates, and snapshots every 60 seconds. Local receive time is captured before JSON parsing. Exchange time is stored separately; Unix epoch zero means the exchange supplied no timestamp.

The bounded queue slows producers when output falls behind and reports a sustained stall as an error. Ctrl-C stops producers, closes connections, drains accepted records, and flushes the writer. The separate verifier reads the supplied format and independently replays updates.

Redundant feeds, activity-based subscription monitoring, multi-exchange adapters, and latency experiments are outside this submission. Timer jitter and recovery gaps are documented rather than hidden.

Run it locally

This is a command-line collector. The terminal shows status; market records go to a binary file that the verifier can read. This documentation page does not connect to Kalshi or receive credentials.

First follow the README setup for Rust and a local read-only Kalshi key. From the repository root:

cargo build --release --locked
mkdir -p data
./target/release/engineering-challenge \
  --markets-per-socket 1000 \
  --run-seconds 180 \
  --output data/walkthrough.sbe

This subscribes to the full regular-market universe and stops after three minutes. Use a new filename each time; file output refuses to overwrite an existing capture. For a smaller smoke test, add --symbols TICKER with a currently active ticker. Ctrl-C also requests a graceful stop.

For stdout, omit --output and redirect with > data/walkthrough.sbe. Logs remain visible on stderr.

Read the status line

FieldMeaning
desiredLive markets selected by discovery.
acknowledgedMarkets whose subscriptions the exchange has acknowledged.
validMarkets with a usable snapshot and book state.
sockets / reconnectsNonempty assigned data shards / data-connection recovery attempts.
snapshots / deltasRecords produced, counted immediately before queueing.
written / queueRecords encoded by the writer / queued records. Encoded does not mean flushed to disk yet.

After startup, look for desired = acknowledged = valid. Watch updates grow and snapshots advance each minute. Equality is a coverage observation, not proof that every exchange event arrived.

Replay the finished capture

./target/release/verify data/walkthrough.sbe

The JSON report counts markets, updates, and snapshots; checks replayed books against later snapshots; and reports snapshot timing. New exchange snapshots can legitimately replace state. Review replacement counts alongside the reconnect log rather than treating every replacement as a replay failure.

Verification

Automated checks cover exact decimals, signed changes, deletion, replacement snapshots, pagination failures, membership changes, sequence gaps, reconnects, ownership handoffs, slow output, broken pipes, minute checkpoints, and SIGINT. Tests use a local exchange fixture and disposable keys.

cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked -- --include-ignored

See the validation record for measured results and the revision tested. The initial submission passed 39 tests; its four-minute live run captured 3.08 million updates across 178,095 markets. The earlier 15-minute run and that final run are recorded separately.

A reading order for code review

The complete submission is larger than a small change. These slices follow the dependencies; each can be understood with its adjacent tests before moving to the next.

  1. util/aligned_sbe_writer.rs: the smallest independent change; preserve framing and the original file API.
  2. book.rs and output.rs: exact arithmetic, canonical sides, and the record queue.
  3. config.rs, auth.rs, and discovery.rs: configuration, signing, and market membership.
  4. feed.rs: subscription commands, acknowledgments, sequence checks, and book validity.
  5. socket.rs: connection recovery, checkpoint timing, and release of market ownership.
  6. collector.rs and main.rs: assignment, service coordination, and graceful shutdown.
  7. bin/verify.rs: independent replay and timing statistics.
  8. tests/common and integration tests: local exchange, recovery/replay, discovery races, scale, stdout, and SIGINT.

A connection to my WLA project

My Weighted Log Analyzer Distributor routes log packets using configured analyzer weights, health checks, and retries. The subscription-monitoring extension raises a related question: how do we notice when a connection is falling behind or a subscription has gone unexpectedly quiet?

A possible next step would measure per-market activity and connection delay, distinguish naturally quiet markets from suspicious stalls, and use those observations to guide resubscription and workload distribution. Any balancing would move whole market subscriptions with an ordered handoff. Per-packet weighted random routing would not preserve the ownership model used here.

This is a proposed direction, not implemented functionality. The collector was designed from the challenge requirements; it does not reuse WLA code. Traffic imbalance should be measured before adding adaptive balancing.
